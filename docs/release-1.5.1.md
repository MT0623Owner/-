# 1.5.1 対面プレイの演出と遅延時の復帰

8EJZの対戦後、本人から「ワードごとの確認が対面では煩雑」「iPadにマスター解除後の確認が残り、押しても戻らず再同期も押せない」と報告。本人は「ワードは確認不要・投票結果だけ全員確認」を選択。

## 変更

- ワード公開は共有の確認待ちを作らず、約2秒の非モーダル演出と公開ログで知らせる。次の人は全員確認を待たずに公開できる。
- 投票結果は全員確認とマスター解除を維持する。
- 投票結果は「画面を閉じる」でローカル表示だけ閉じられる。共有の確認には数えない。同じイベントの同期では勝手に開き直さず、待機画面から再表示できる。
- ポップアップ内の再同期・閉じる、画面ヘッダーの再同期は送信待ち中でも利用できる。

## 再現した不具合の経路

購読通知が遅れ、共有状態はマスターによって先へ進んでいるが端末は古い演出を表示している場合、古い確認は正しく無変更になる。そのトランザクションが返す最新状態を画面が捨て、購読通知だけを待っていたため表示が残った。

操作の返り値を反映し、通知が来なくても復帰できるよう変更。操作開始後に新しい通知を受けた場合や退出・別部屋へ移った場合は、遅れた返り値で画面を巻き戻さない。再同期の読み取りにも同じ競合対策を入れた。

これは通知を遅延させた再現環境で確認したアプリ側の問題。実物iPadの通信ログは取得しておらず、iPadの恒常的な通信遅延そのものの原因・解消は未確認。

## 検証

- 構文検査・既存core・Node15件成功。
- Chromium / WebKitで、通知なしの古い確認、送信停止中の再同期とローカル閉じる、確認画面の再表示、古い応答による巻き戻し防止を確認。
- ワード演出中も画面がモーダルで操作不能にならず、約2秒で閉じることを確認。旧5秒表示を前提にした2件は新仕様へ更新。

全員が再読み込みして1.5.1を確認し、新規部屋で開始する。
