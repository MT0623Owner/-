# 1.6.0 マスター自身のキーによるAIお題生成

本人は「マスターが自分のAPIキーを入力して使う」を選択。既存のGemini接続を基に、通信をai-topics.jsへ分離して生成の検査・再試行・失敗時の操作を実装。今回の対応プロバイダーはGeminiのみ。他社への変更時は通信アダプターを追加できるが、他社キーにはまだ対応していない。

## 生成ポリシー

お題・制約・ヒントと、制約に合う／合わない回答例をJSONで取得。適合例は最低6個、週数×人狼数＋2がより多ければその数を要求。不適合例も最低6個。型・長さ・正規化後の重複・両側の重複・一部の曖昧表現・ヒントの直接引用を検査する。

この検査は意味や事実の正しさを証明しない。別名・事実誤認・難度・ヒントの強さは人間のプレイで調整する。回答例は候補の検査にのみ用い、部屋へ保存しない。

形式・品質の不適合だけ1回再生成。APIの認証・利用上限・モデル不存在は再試行せず案内する。全体30秒で中止し、最大2リクエスト。ローカルへ黙って切り替えず、ロビーに留まる。

マスターのタブのセッション保存と削除操作を用意。キーはGoogleへヘッダーで送り、URL・部屋データへ含めない。上流のエラー本文も表示しない。人数の事前確認と、生成中に接続やゲーム状態が変わった際の開始中止を入れた。

## 検証と限界

Nodeで検査、再生成上限、利用上限エラーの秘匿、タイムアウトを検証。Chromium/WebKitでAPI応答を差し替え、生成から役職確認、失敗時のロビー維持、明示的ローカル切替、キー削除、人数不足時にAPIを呼ばないことを検証。

実キーは提供されておらず、実Gemini API・課金・生成された例の正確さは未検証。初回はマスターがアプリにキーを入力して確認する。キーをチャットへ貼る必要はない。
