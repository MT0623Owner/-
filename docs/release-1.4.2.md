# 1.4.2 通信待ちからの復帰案内

2026-10-15、C9DZのiPhoneマスター端末で参加者一覧が更新されず、「送信中…」が続いた。本人は同じタブを再読み込みし、前回の部屋から再入室して復帰した。

## 調査と変更

- 送信処理のPromiseが完了しない間、重複操作を防ぐためにボタンが無効のままになる。従来は復帰方法の案内がなかった。
- 15秒以上待つ場合は、読み込み直しと「前回の部屋」からの再入室を案内する。案内のボタンは通信待ちでも押せる。通信が完了したら案内を閉じる。
- 書き込みは実際には完了している可能性があるため、時間切れを理由に自動再送したり、二重送信防止を解除したりしない。
- 別途、再同期の読み取りが返らないと再試行もできなくなることを再現。読み取りと認証待ちを合わせて15秒で打ち切り、再試行できるようにした。古い読み取りが後から完了しても画面に適用しない。
- 既存の部屋・役職・勝敗ルール・Firebase設定は変更しない。

## 検証範囲

構文チェック、既存core、Node回帰・同期11件、ChromiumとWebKitのブラウザテスト64件（各32件）が成功。送信待ちを継続させても復帰ボタンが押せること、次の書き込み操作は無効を維持すること、送信完了後に案内が閉じること、再同期の時間切れ後に再試行できること、古い読み取り結果が参加者一覧を巻き戻さないことを確認した。修正前には、復帰案内がないこと・再同期を再試行できないことを両エンジンの失敗テストで再現した。

今回再現したのは通信が応答しない場合のアプリ側の挙動である。本人のiPhoneの通信ログは取得できておらず、実機で通信が止まった直接の原因は未特定。SafariやFirebaseの通信停止自体を修正したという主張はしない。本人の復帰は修正公開前の再読み込みによるものである。
