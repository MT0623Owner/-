# 1.5.2 思考画面の描画キャッシュ修正

本人からマスターのスクリーンショットで `null is not an object (evaluating panel.querySelector(".thinking-progress").textContent ...)` を報告された。

## 再現と原因

思考フェーズを一度描画し、投票結果の古い通知が届いて確認待ち表示へ置き換わり、その後に同じ週・期限の思考状態へ戻ると発生した。確認待ちの早期returnがフェーズ変更と描画キャッシュの更新を通らないため、思考画面を描画済みと誤認し、存在しない人数表示を更新していた。

WebKitのマスター画面で画像と同じ例外を再現。Chromium/WebKit、マスター/参加者の4条件で修正前に失敗を確認した。

## 修正・検証

確認待ちもフェーズ変更の記録と共通描画処理を通す。nullを無視するのではなく、必要な思考画面を作り直す。

修正後は4条件で、確認画面が消え、人数表示と有効な思考完了ボタンが戻り、完了操作が働くことを確認。構文検査・既存core・Node15件も成功。

実機で通知が遅延・前後する根本原因の特定とは分ける。今回確認したのは、その順序で通知を受けた際の描画例外。全員再読み込みで1.5.2へ揃える。
