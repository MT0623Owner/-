# 制約ワードウルフ

マスター端末で部屋を作り、参加者が部屋コードで入室する同期型の制約ワードウルフです。

## 公開版・参加方法

- 公開URL: https://mt0623owner.github.io/-/
- バージョン: 1.5.0
- GitHub: https://github.com/MT0623Owner/-
- サイトを開くQRコード: [site-qr.svg](assets/site-qr.svg)

[![制約ワードウルフの公開サイトを開くQRコード](assets/site-qr.svg)](https://mt0623owner.github.io/-/)

スマホのカメラで上のQRコードを読み取ると、公開サイトを開けます。画像のクリックでも開けます。

マスター画面の「招待」を押すと、部屋コード・部屋専用QRコード・参加URLをまとめて確認できます。
参加者はスマホのカメラで読み取るかURLを開き、名前を入力して参加します。
QRコードは端末内で生成し、外部のQR生成サービスは使いません。
部屋コードの手入力も引き続き利用できます。

## 1.5.0の変更

- ワード公開・投票結果の演出は「確認した」を押す方式へ変更。容疑者・観戦マスターも含む全員の確認がそろうまで、次の開示・投票・タイマー開始を停止します。
- 未確認者を表示。離席・通信切れの場合はマスターの「未確認者がいても進める」で解除できます。
- 再入室でも確認待ちを復元し、確認済みの人に再確認を求めません。動きを減らす設定でも確認は必要です。
- 部屋コードとQRは画面上部の「招待」にまとめ、フェーズによる上下移動を解消しました。
- 人数が足りるようになった後も残る「3人以上必要」の古い警告を消します。

**全員がページを再読み込みしてから、新しい部屋で開始してください。** 旧版との混在には対応しません。役職のルール説明は従来どおり個人用で、今回の全員待ちは公開ワードと投票結果が対象です。

## 1.4.2の変更

- 通信処理が15秒以上続いた場合は、画面の再読み込みと「前回の部屋」からの再入室を案内します。送信が完了している可能性があるため、自動的に同じ操作を送り直しません。
- 再同期は15秒で待機を打ち切り、もう一度試せるようにしました。時間切れ後に返ってきた古い結果で参加者一覧を巻き戻しません。
- iPhoneで「送信中…」が続いた事例への復帰案内です。端末側で通信が止まった直接の原因を特定・解消したという意味ではありません。詳しくは [通信待ちの検証記録](docs/release-1.4.2.md) を参照してください。

## 1.4.1の変更

実際の対戦で寄せられた「演出が速い」「投票中にワードを比較しづらい」「ルールが読みにくい」を改善しました。

- ワードの演出を約5秒に延長。投票結果も集計後4.5秒残し、スキップする余裕を確保。連続したワードは順番に表示し、スキップで待機分も閉じます。
- 話し合い・通常投票・最終告発では、**1人1行でワードを横並び**に表示。「○週目」の繰り返しを省き、左から古い順、青緑が各参加者の最新ワードです。
- 比較表を投票操作の直前へ移し、自分のカードはコンパクトに表示。4人・3週の標準的な長さのワードならスマホの一画面で比較でき、カードは必要なときに開けます。週数が多いときは表の中だけ横にスクロールできます。
- 結果のワードも1人1行に整理。制約に合うかどうかの手動の印は引き続き利用できます。
- 青緑・黄・紫のアクセントで、公開ワード・容疑者／投票結果・操作／ルールを区別。
- 役職別のルールは冒頭に「すること」「禁止」を太字で表示。発言例・共通ルール・勝敗の詳しい説明は折りたたみ式にしました。

検証範囲と後回しにしたマスター／リーダー分離案は [1.4.1の変更記録](docs/release-1.4.1.md) を参照してください。

## Firebase設定

1. FirebaseでWebアプリを作成します。
2. Authenticationで「匿名」を有効化します。
3. Cloud Firestoreを作成します。
4. `firebase-config.example.js` を参考に、`firebase-config.js` の `window.CWW_FIREBASE_CONFIG = null;` をFirebase Web configへ置き換えます。
5. Firestore Rulesには `firebase.rules` の内容を設定してください。

Firestore Rulesに貼るのは、次のような `rules_version = '2';` から始まるコードだけです。
Realtime Database用のJSON形式、たとえば `{ "rules": { ".read": true, ".write": true } }` は使いません。

```js
rules_version = '2';

service cloud.firestore {
  match /databases/{database}/documents {
    match /artifacts/{appId}/public/data/rooms/{roomCode} {
      allow read, write: if request.auth != null;
    }
  }
}
```

Firebase Web configはブラウザアプリ用の公開設定です。秘密鍵ではありません。

## お題の自動生成

「お任せ(ローカル生成)」は外部AI APIを使わず、アプリ内のローカル生成器でお題・制約・占い師ヒントを作ります。
通信、APIキー、無料枠制限に依存しないため、GitHub Pages上で安定して動きます。
生成レベルは「普通」「ちょい知識」「マニアック」から選べます。お題だけ指定することもでき、空欄の場合はお題も自動生成します。
生成された内容はゲーム開始後の参加者カードにだけ表示されます。

「お任せ(外部AI / Gemini)」では、マスターがGemini APIキーとモデル名を入力して、ゲーム開始時にお題・制約・占い師ヒントを生成できます。
既定モデルは安定版の `gemini-2.5-flash` です。指定モデルが存在しない、または `generateContent` に未対応の場合は、別のFlash系モデルへ自動再試行します。
APIキーはFirestoreの部屋データには保存せず、マスター端末のセッション中だけ使います。
APIエラー、通信失敗、JSONパース失敗時はローカル生成へ即時フォールバックします。

マスターも参加する設定を有効にすると、マスター端末にも自分用のカード、伏せ入力、開示、投票パネルが表示されます。

## 進行仕様

ゲーム開始後、まず全員にお題と役職カードを表示します。全員が「確認」を押すと、マスター画面に「ゲーム開始」ボタンが表示され、設定した秒数（初期値30秒）の思考時間へ進みます。
入力する全員の思考完了、または制限時間で伏せ入力画面に切り替わります。送信済みの参加者は待機表示になり、マスターは未送信者がいても強制的に開示フェーズへ進められます。
占い師を入れる設定は参加者が4人以上のとき有効です。1週目は選ばれた本人にも村人として表示され、2週目開始時に占い師へ切り替わり、ヒントが表示されます。
1週目の通常投票だけ「投票しない」を選べます。スキップが最多の場合、誰も容疑者にならず次週へ進みます。
前回の部屋コードと名前は端末内に保存され、ホーム画面から再入室できます。保存情報は「削除」で消せます。

## 占い師のルール

占い師は村人陣営です。2週目開始時に、本人だけが自分の役職と人狼の制約に関係するヒントを一つ知ります。人狼が誰かを直接知る能力ではありません。

- ゲーム終了まで、全員が占い師の名乗り・偽名乗りをしてはいけません。
- 占い師はヒントそのものや、それを言い換えた内容を秘密の情報として教えてはいけません。役職カードを見せることも禁止です。
- ヒントをワード選び・推理・投票に利用することは自由です。そこから得た推理を、自分の気づきとして話せます。秘密の情報を持つことを信用の根拠にせず、公開ワードを根拠に説明します。
- 人狼に似たワードを出して探りを入れるかどうかは本人の自由です。
- 容疑者になっても秘密を守ります。通常の容疑者と同じく、以後のワード入力・通常投票はできませんが、話し合いと最終告発にはヒントを利用できます。
- ゲーム終了後は役職・ヒントを公開し、振り返れます。

例：ヒントが「飼育」の場合

| 発言・行動 | 可否 |
| --- | --- |
| 自分のワードとして「ハムスター」を出す | 可 |
| 公開された「ハムスター」「カメ」を見て「どちらも家で飼える動物だよね」と推理する | 可 |
| 「占い師です。ヒントは飼育でした」と話す | 不可 |
| 「役職は言えないけど、もらった情報はペット関係」と伝える | 不可 |

発言に関するルールは参加者同士で守ります。アプリは音声の判定や違反の自動処罰を行いません。話し合いは会話で行うため、アプリ内の発言欄はありません。

## ローカルテスト

```bash
npm ci --ignore-scripts
npm run check
npm test
npx playwright install chromium webkit
npm run test:browser
```

ブラウザテストはFirebase接続を差し替え、実際の画面操作・入力保持・QRのデコードを検証します。
実Firebaseの認証や権限は、このテストの検証範囲外です。
GitHub Actionsの `Checks` でも同じ検証を実行します。

ローカルで画面を開く場合は `node tests/serve.cjs` を実行し、
http://127.0.0.1:4173/ にアクセスしてください。

実Firebaseを使う通しテストは明示的に有効化した場合だけ実行できます。
3つの独立したブラウザセッションで1部屋を作成し、投票・勝敗表示まで操作した後、
そのテスト部屋だけを削除します。匿名認証ユーザーがテスト分作成されます。
ローカルサーバーを起動した状態で、PowerShellから以下を実行します。

```powershell
$env:CWW_LIVE_TEST = '1'
node tests/live-smoke.cjs
```

公開版を確認する場合は `CWW_TEST_URL` に公開URLを指定します。
テストは実際のFirebaseへ読み書きするため、通常のCIには含めていません。
